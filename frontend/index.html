    Platform Features & Capabilities
    
                
    Active detection mechanisms, architecture components, and operational boundaries.
    
              
    
            
    
            
    
              
              
    
                
    
                  🎯
                  
    Calibrated Probabilities
    
                  
    LinearSVC paired with Platt scaling (CalibratedClassifierCV) generates reliable, well-calibrated posterior probabilities rather than raw uncalibrated distances.
    
                
    
                
    
                  🔎
                  
    Explainable Token Cues
    
                  
    In-text n-gram highlighting isolates spam-driving (▲) and legitimate-driving (▼) vocabulary with accessible, non-color-only directional indicators.
    
                
    
                
    
                  ✉️
                  
    MIME Header Inspection
    
                  
    Parses authentic .eml files via Python's standard email module, auditing SPF, DKIM, DMARC alignment, Received hop counts, and From vs. Reply-To mismatches.
    
                
    
                
    
                  🔗
                  
    Suspicious Link Heuristics
    
                  
    Identifies IP-literal hosts, known URL shorteners, multiple redirect constructs, and credential phishing link patterns within email bodies.
    
                
    
                
    
                  🖼️
                  
    Client-Side Image OCR
    
                  
    Zero-upload visual spam inspection powered by self-hosted Tesseract.js running WebAssembly in an isolated in-browser Web Worker.
    
                
    
                
    
                  🔒
                  
    Local-Only Analytics
    
                  
    Scan telemetry resides strictly on the user's device in IndexedDB. Zero email text or telemetry is logged or persisted to backend servers.

    Known Limitations & Operational Failure Modes
    
                
      
                  
    • Historical lexical bias: The Enron corpus reflects early-2000s corporate language and transactions; modern zero-day phrasing, cryptocurrency scams, or synthetic AI-generated lures may exhibit lower vocabulary coverage.
      • 
                  
    • English-oriented preprocessing: NFKD normalization intentionally decomposes and strips diacritic marks. Non-Latin scripts (e.g. Cyrillic, CJK, Arabic) provide sparse n-gram matches and automatically trigger the uncertainty band for human review.
      • 
                  
    • Short message ambiguity: Ultra-short messages (<10 words) lack sufficient statistical context to differentiate casual notes from terse lures, prompting a “Needs Review” classification.
      • 
                  
    • Adversarial obfuscation: Deliberate spaced typos (e.g. ‘c a s h’), zero-width unicode insertions, or base64 evasion in raw HTML bypass standard TF-IDF n-grams unless pre-sanitized by the heuristic signal parser.

                  ⚡
                  
    
                    Rate Limiting (Flask-Limiter):
                    All client requests are subject to sane sliding-window rate limits: 60 requests / minute on /api/analyze and /api/predict; 120 requests / minute on /api/model-info; /api/health is exempt. Limits are tracked in-memory per server process and reset on instance restart. Exceeding limits returns a standard HTTP 429 JSON response.

    Privacy & Security Architecture
    
                
    Zero server-side persistence, local-only client storage, and auditable security guarantees.
    
              
    
            
    

            
    
              
              
    
                
                
    
                  
    
                    ⚡
                    
    What is Processed
    
                  
    
                  
    
                    When you submit text or email headers to POST /api/analyze, the payload is processed strictly in-memory during HTTP request execution.
                  
    
                  
      
                    
    • Held in volatile RAM only to compute TF-IDF feature vectors and heuristic threat rules.
      • 
                    
    • Memory buffers are cleared immediately once the JSON response is delivered.
      • 
                    
    • Zero server background logging or disk caching of raw email bodies or headers.
      • 
                  
    
                
    

                
                
    
                  
    
                    💾
                    
    What is Stored (Local Only)
    
                  
    
                  
    
                    Scan telemetry and configuration exist exclusively within your browser's local sandbox.
                  
    
                  
      
                    
    • IndexedDB (mailguard_db): Scan timestamps, truncated subject snippets (≤60 chars), risk scores, and verdicts.
      • 
                    
    • localStorage: Sensitivity levels, URL scan options, header scan options, and visual theme.
      • 
                    
    • User Control: Clear all history or export to CSV/JSON at any time. History never leaves this device.
      • 
                  
    
                
    

                
                
    
                  
    
                    🚫
                    
    What is Never Stored
    
                  
    
                  
    
                    MailGuard AI operates without server-side databases or third-party trackers.
                  
    
                  
      
                    
    • Zero Server Database: No email text or subject lines are written to disk or databases.
      • 
                    
    • Zero Server Image Handling: Image OCR runs 100% in-browser via WebAssembly; images never leave your machine.
      • 
                    
    • Zero Tracking: No tracking cookies, external analytics scripts, or user fingerprinting.
      • 
                  
    
                
    

                
                
    
                  
    
                    🛠️
                    
    Technology Stack
    
                  
    
                  
    
                    Minimal, self-contained architecture engineered for auditable security.
                  
    
                  
      
                    
    • ML Pipeline: scikit-learn (LinearSVC + Platt scaling via CalibratedClassifierCV, TF-IDF n-grams).
      • 
                    
    • Backend API: Python 3.10+, Flask, Flask-Limiter, Werkzeug ProxyFix.
      • 
                    
    • Client Runtime: Vanilla ES6+, CSS Tokens, IndexedDB, self-hosted Tesseract.js (WASM).
      • 
                    
    • Content Security Policy: Strict CSP Level 3, zero CDNs, zero inline scripts or styles.
